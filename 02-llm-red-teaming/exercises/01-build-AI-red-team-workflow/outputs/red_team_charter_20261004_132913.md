## Objectives

The primary objective is to rigorously evaluate EnterpriseSummarizer’s limited internal deployment for risks related to its Retrieval-Augmented Generation (RAG) pipeline and associated tooling. The red team will simulate advanced adversarial scenarios to identify weaknesses that could lead to unauthorized data access, leakage, or exfiltration that compromises departmental boundaries and data confidentiality.

Key prioritized attack vectors to validate include:

1. **Indirect Prompt Injection via Retrieved Document Content** — Assess if embedded instructions in retrieved documents can override system LLM instructions and leak restricted data.  
2. **Retrieval Authorization Bypass via Client-Supplied Identity and Department** — Test whether client-supplied `department` and `user_id` in API requests can be exploited to escalate access across departments.  
3. **Data Leakage through Citation Metadata and Verbatim Confidential Excerpts** — Verify if document titles of unauthorized documents or verbatim sensitive excerpts leak in summaries or citations.  
4. **Insecure Tool Use: Unauthorized Exports of Summaries** — Probe export endpoint for potential data exfiltration by exporting summaries outside allowed workspace paths or departments.  
5. **API Abuse: Bulk Enumeration via Large Document Scopes and Metadata Filters** — Investigate risks from request size, scope manipulation, and absence of export rate limiting.  
6. **Direct Prompt Injection via Crafted User Queries** — Examine the LLM’s resistance to direct user prompt injections that try to override instructions or extract sensitive content.  
7. **Logging and Telemetry Exposure** — Review if sampled prompt texts or metadata in centralized logs expose sensitive information to broader audience than intended.  
8. **Monitoring and Detection Gaps** — Evaluate detection of anomalous retrieval patterns or slow exfiltration tactics given current alerting limitations.

## Scope

### In Scope

- All interactions with the Summarization API `/summaries` and `/tools/export` endpoints within the limited deployment environment using test and synthetic data.
- Evaluation of authorization enforcement between API Gateway, Summarization API, retrieval policy filter, vector database, and LLM endpoint.
- Analysis of prompt injection attack vectors through both user queries and retrieved documents.
- Authorization control validation for document retrieval scopes and export workspace destinations.
- Review of logs, telemetry, and monitoring capabilities regarding sensitive data exposure and alerting gaps.
- API abuse scenarios within the documented per-user rate limits and input schema constraints.

### Out of Scope

- Supply chain risk assessments related to CI/CD pipeline, container registry, or third-party hosted LLM infrastructure.
- Exploitation scenarios involving privileged groups or metadata poisoning without explicit evidence or documented controls.
- Frontend or UI application vulnerabilities, including XSS or CSRF issues not described in the API or deployment context.
- Vector database injection or poisoning attacks not evidenced in architecture or API documentation.

## Rules of Engagement

1. All testing will occur on the approved limited internal deployment, using synthetic or non-production test accounts unless otherwise authorized by system owners.
2. No destructive testing or attempts to escalate beyond documented internal users and departments.
3. Maintain confidentiality of all document contents accessed during testing; do not export or share real sensitive data outside the engagement.
4. Avoid actions that may disrupt normal enterprise services or violate enterprise identity provider rules.
5. All identified risks will be reported responsibly without including exploit payloads or sensitive credentials.
6. Respect export rate limits and refrain from flooding API endpoints to prevent denial of service conditions.
7. Do not test supply chain or CI/CD components absent explicit scope authorization.

## Success Criteria

| Attack Vector                                        | Success Metric                                                                                      |
|-----------------------------------------------------|---------------------------------------------------------------------------------------------------|
| Indirect Prompt Injection via Retrieved Document Content | Demonstrated execution of embedded instructions causing unauthorized data disclosure in summaries. |
| Retrieval Authorization Bypass via Client-Supplied Identity and Department | Successful retrieval of restricted or cross-department documents by manipulating `user_id` or `department` parameters. |
| Data Leakage through Citation Metadata and Verbatim Excerpts | Citations or summaries exposing document IDs, titles, or verbatim confidential content outside authorized scope. |
| Insecure Tool Use: Unauthorized Exports             | Export actions succeeding to write summaries to workspace locations outside the requestor's department or allowed destination list. |
| API Abuse via Bulk Enumeration                        | Ability to enumerate document existence or content using large `document_scope` lists, complex metadata filters, or multiple requests under rate limit. |
| Direct Prompt Injection via User Queries             | Generation of summaries violating system instructions or leaking restricted information triggered by crafted queries. |
| Logging and Telemetry Exposure                        | Discovery of sensitive prompt text, document metadata, or export destination paths accessible to broader log viewers. |
| Monitoring and Detection Gaps                         | Execution of anomalous retrieval or export patterns without triggering alerts or automated detection. |

## Deliverables

1. Completed Red Team Charter (this document).  
2. Prioritized Attack Vector List with detailed test ideas and mitigation notes.  
3. Evidence-backed findings including test results, logs, and supporting data.  
4. Recommendations for specific mitigating controls and monitoring improvements.

## Assessment Notes

- All findings generated from the detailed review of system architecture, API specification, model card, and infrastructure notes should be validated with controlled tests using authorized test users.  
- Red team members must carefully differentiate between incomplete metadata and true authorization bypass scenarios by correlating retrieved document classifications and user groups.  
- Prompt injection testing should cover both direct queries and evaluation of outputs influenced by retrieved document content, including embedded instructions or email fragments.  
- Validate export controls by systematically testing allowed and disallowed workspace destinations with both legitimate and crafted paths, verifying application-layer enforcement.  
- Bulk enumeration attempts should respect rate limits to emulate realistic adversaries and detect monitoring gaps without causing service disruption.  
- Review log sampling for sensitive data exposure with appropriate access permissions to assess risk scope; provide recommendations for redaction or access control tightening as needed.  
- Where evidence on supply chain and metadata filter injection is absent, these should be deferred pending further infrastructure insights.  
- Report all findings as hypotheses with appropriate confidence levels and mitigation suggestions rather than confirmed vulnerabilities to guide engineering remediation and policy updates.
