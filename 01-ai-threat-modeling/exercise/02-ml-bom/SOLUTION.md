# ML-BOM: Machine Learning Bill of Materials

## System Overview

ClinicalCompanion is an internal RAG-based question-answering system for Cascadia Health's nurses, hospitalists, and pharmacists, deployed on an Amazon Bedrock AgentCore harness, which retrieves from a Managed Knowledge Base through an AgentCore Gateway. It uses two AI models with distinct roles: Amazon Titan Text Embeddings V2 converts both clinical staff queries and knowledge base documents into dense vector representations for semantic similarity retrieval, and Anthropic Claude Sonnet 4.5 generates grounded natural-language responses from the retrieved clinical document context and the clinician's original question. A security failure in the embedding model affects retrieval integrity (what content reaches the generation model); a security failure in the generation model affects response integrity (what clinical information the clinician sees).

### Intended Use

Amazon Titan Text Embeddings V2 is used in ClinicalCompanion exclusively for semantic similarity search within the RAG retrieval pipeline. It converts clinical staff queries and knowledge base document chunks into fixed-length vector representations at both ingest time (documents → vectors stored in the Managed Knowledge Base vector store) and query time (user question → query vector for similarity search). It is not used for and cannot produce text output, answer questions, or perform any generative task. Its output is a numerical vector used internally by the retrieval system — clinical staff never see the embeddings directly.

---

### Out of Scope Use

- Text generation or question answering (this model cannot produce text output)
- Image, audio, or multimodal processing
- Any application that expects human-readable text as model output
- Fine-tuning or model customization for the ClinicalCompanion use case
- Processing documents longer than 8,192 tokens without chunking

---

### Misuse / Malicious Use

- **Embedding poisoning via adversarial documents:** An attacker crafts a document that, when embedded, produces a vector close to many common query vectors — causing the document to be retrieved across a wide range of clinical staff queries. This "retrieval hijacking" delivers the attacker's content to the generation model regardless of what the clinician actually asked.
- **Embedding collision exploitation:** An attacker engineers a malicious document to have a similar embedding to a high-trust document (e.g., an official clinical guideline), causing the malicious document to displace or supplement the trusted document in retrieval results for related queries. This can surface unrelated or contraindicated clinical content.
- **Ingest-time pipeline abuse:** If the embedding model API is accessible with over-broad IAM permissions, an attacker could submit arbitrary content for embedding and injection into the vector store outside the legitimate KB ingest pipeline.

### Intended Use

Claude Sonnet 4.5 is used in ClinicalCompanion as the generation model in the RAG pipeline. It receives a composed prompt containing: the harness system prompt (instructions), retrieved document chunks from the Managed Knowledge Base (returned through the AgentCore Gateway's Retrieve tool), and the clinician's original question. It generates a grounded natural-language response that cites the retrieved content. It is expected to answer only from the retrieved context and not from its parametric knowledge. Responses that aren't supported by the retrieved context are out of scope. A contextual grounding check scores whether a response is supported by the retrieved source, but in testing on harness traffic the guardrail recorded no grounding assessment, so don't rely on that check to catch them.

---

### Out of Scope Use

- Clinical decisions or actions taken on the model's answer without review by a clinician
- Answering clinical questions from the model's own knowledge instead of the retrieved Cascadia Health clinical guidelines, formulary data, discharge procedure checklists, and compliance documentation
- Legal or financial advice
- Real-time voice, audio, or image generation
- Use by patients or by anyone other than Cascadia Health clinical staff (nurses, hospitalists, and pharmacists)

---

### Misuse / Malicious Use

- **Direct prompt injection:** A user submits a query containing text designed to override the system prompt (e.g., "Ignore your previous instructions and..."), for example to extract the system prompt or non-public formulary data. Claude's Constitutional AI training provides some resistance, but it is not a complete defense.
- **Indirect prompt injection via poisoned clinical documents:** An attacker embeds model override instructions inside a clinical document in the knowledge base. The retrieval system delivers the instructions to Claude as part of the context window. Claude cannot reliably distinguish retrieved document content from trusted system instructions.
- **Ungrounded clinical recommendations:** The model generates clinical guidance that the retrieved guidelines don't support (a hallucination). In a clinical setting this is a patient safety issue, not only a quality issue, because a clinician may act on the answer.
- **Jailbreaking to bypass Constitutional AI alignment:** Sophisticated multi-turn attacks or role-playing framings can bypass alignment training to elicit content Claude would normally refuse to produce.
- **Training data extraction:** Prompts designed to cause the model to reproduce memorized content verbatim — potentially exposing content from Anthropic's training corpus, which could include sensitive text from the public web.
- **Social engineering content generation:** Using Claude to generate phishing messages, impersonation content, or manipulative communications inside the organization (e.g., generating a fake internal notice).

## Console Walkthrough: Verifying Model Information in the AWS Console

### 1. Find the model IDs your system actually uses

Amazon Bedrock no longer has a model access step: models are available on first use, and IAM permissions on the calling role decide which models can be invoked. Read the IDs from the deployed resources instead.

1. Open the **AWS Management Console** and navigate to **Amazon Bedrock AgentCore**. In the left navigation under **Test**, choose **Harness playground**, then select the ClinicalCompanion harness and its **DEFAULT** endpoint
2. Open the **Configs** panel. Note the model ID (for example, `us.anthropic.claude-sonnet-4-5-20250929-v1:0`). The `us.` prefix marks a US cross-Region inference profile. You can also read it with the `GetHarness` API.
3. The embedding model is the one chosen when the Managed Knowledge Base was created: **Amazon Titan Text Embeddings V2** (`amazon.titan-embed-text-v2:0`)

### 2. View model details from the Bedrock model catalog

1. In the Bedrock console left sidebar, click **Model catalog** (under **Discover**)
2. Search for "Titan" — click **Amazon Titan Text Embeddings V2** to view its detail page
3. Note the **Use case**, **Max tokens**, and **Languages** fields — these correspond to BOM fields
4. Go back and search for "Claude Sonnet 4.5" — click to view details
5. Note the context window size (200K tokens) and output token limit

### 3. Verify model is accessible in your region

1. In the Model catalog, check the **AWS Regions** field for each model
2. Ensure `us-east-1` is listed — this is the deployment region for ClinicalCompanion
3. If your deployment region is different, update the BOM's deployment environment field accordingly
4. Record the inference profile too. With a US cross-Region profile, requests from a us-east-1 harness can be processed in other US Regions. Model invocation log records show where each request ran in the `inferenceRegion` field.

### 4. Link to vendor documentation

- From the Titan model detail page, click the **Documentation** link — this takes you to the AWS Bedrock Titan documentation
- For Claude, the Anthropic model card documentation is at https://docs.anthropic.com/en/docs/about-claude/models
- Record these URLs in the BOM's Source / Documentation URL field
