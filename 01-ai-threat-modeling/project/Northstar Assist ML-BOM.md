## System Overview

Northstar Assist is an internal question-answering assistant for Northstar Technologies employees. It answers questions about company policies, procedures and internal documentation. It is a retrieval-augmented generation (RAG) agent built on **Amazon Bedrock AgentCore**:

**How the components work together**

1. **Ingest (offline).** The data source `northstar-documents` (`NTXBJ668Z7`) uses the **KB service role** to read 30 documents from `s3://northstar-assist-kb-chrst/northstar-knowledge-base/`. It parses each file with smart parsing, chunks it, embeds each chunk with **Titan Text Embeddings V2** (1,024 dimensions, FLOAT32), and stores the vectors with their chunk text and metadata in the AWS-managed vector store of **Managed Knowledge Base** `ZCAWWBRBXU`. Ingestion job `ZPFE9LWPAN` (2026-10-02, 16:43–16:47 UTC) scanned 30 documents, indexed 30 and had 0 failures.
2. **Query (online).** The client calls `InvokeHarness` with a user message and a session ID. The **harness** assumes its **execution role** and calls **Claude Haiku 4.5** (Converse streaming). It sends the system prompt, the message and the gateway's tool list.
3. Claude decides to call the knowledge base tool. The harness signs an MCP request to the **AgentCore Gateway** using IAM. The gateway assumes its **service role** and calls `bedrock:Retrieve` on knowledge base `ZCAWWBRBXU`.
4. The knowledge base embeds the query with **Titan V2** and runs a similarity search. It returns the 5 nearest chunks with their text, S3 location, metadata (`_source_uri`, `_document_title`, `_file_type`, `_chunk_id`, …) and relevance score.
5. The chunks go back to Claude as the tool result. Claude writes an answer that names the source document, and the harness streams it back to the client.

**Distinct security failure modes**

Each component fails in a different way and needs different controls. That is why each one is inventoried separately.

| Component | What it controls | How it fails | Consequence |
|---|---|---|---|
| Claude Haiku 4.5 (generation) | **Response integrity**: what the user reads | Direct or indirect prompt injection, jailbreak, hallucination, system-prompt leakage, over-disclosure of retrieved PII | Wrong, harmful or confidential content reaches the user. The model can be steered into making unintended tool calls. |
| Titan Text Embeddings V2 (encoder) | **Retrieval integrity**: which chunks reach the LLM | Adversarial or keyword-stuffed documents produce vectors close to many queries ("retrieval hijacking"). Embedding collisions push legitimate documents out of the results. | Attacker-chosen content enters the context window for unrelated questions. This is the delivery path for indirect prompt injection. The vectors themselves can partially leak the text they encode (embedding inversion). |
| Knowledge source and S3 bucket | **Data integrity and confidentiality at rest** | Unauthorized `PutObject`/`DeleteObject` (poisoning or wiping), sensitive data in the corpus | Poisoned answers after the next sync, or bulk exfiltration of raw documents |
| Managed KB vector store | **Index integrity** | Stale or poisoned vectors, unreviewed re-syncs, no per-document access control on retrieval | Every caller can retrieve every chunk, including PII. Deleting all sources wipes the index, because deletion protection is off. |
| AgentCore Gateway | **Tool exposure** | Extra or misconfigured targets, no rate limits, verbose (`DEBUG`) errors | Callers or the model reach more data than intended. Request floods go unchecked, and error messages leak internal details. |
| Harness | **Orchestration** | `InvokeHarness` callers can override the model, system prompt and tools per call. No guardrail is attached. | Anyone with `bedrock-agentcore:InvokeHarness` can remove the system prompt's restrictions or swap in another model or tool |
| IAM roles | **Blast radius** | Wildcard model, tool and file-system permissions on the harness role | A hijacked or overridden agent can call any model in any Region and start Browser or Code Interpreter sessions |

## 3. Usage

### 3.1 Intended Use

Claude Haiku 4.5 is the reasoning and generation model in the Northstar Assist agent loop. Its configured system prompt (harness version 1) reads:

> *"You are Northstar Assist, Northstar Technologies' internal employee assistant. Your job is to help Northstar employees find accurate answers to questions about company policies, procedures, and internal documentation. Always search the Northstar knowledge base tool before answering a question about Northstar. Base your answers only on the retrieved documents and name the source document you used. Do not make up policy details. If the knowledge base does not contain relevant information, say so clearly. Do not guess. Do not discuss topics unrelated to Northstar operations."*

For each employee question, it calls the knowledge base `Retrieve` tool and then writes a concise answer based only on the retrieved Northstar chunks, naming the source document. Typical questions cover HR and company policies, the security policy, product features, troubleshooting, the API authentication guide, SLA and compliance summaries, and release notes. Users are authenticated Northstar employees.

### 3.2 Out of Scope Usage

- Answering from the model's own knowledge when the knowledge base has no relevant content. The system prompt tells it to say so instead.
- Topics unrelated to Northstar operations
- HR, legal, financial, security-incident or disciplinary decisions made on the answer without human review
- Bulk export or listing of personal data, such as "list every employee's email and extension" or "list all customer contacts and revenue"
- Use by customers, partners or the public. Northstar Assist is internal only.
- Writing or running code, browsing the web, or taking actions in other systems. The only tool configured is Retrieve, even though the execution role would allow Browser and Code Interpreter (see F-07).
- Image, audio or file inputs, and processing regulated data such as PHI or payment card data

### 3.3 Misuse or Malicious Use

- **Direct prompt injection and jailbreaks:** for example "ignore previous instructions…", role-play framings, or multi-turn escalation to override the system prompt, reveal it, or answer off-topic. Constitutional AI training resists this but does not prevent it, and no guardrail is attached (F-08).
- **Indirect prompt injection:** instructions planted in a knowledge base document (for example a modified HTML handbook, a CSV `notes` field, or text inside an image, since image extraction is enabled) reach the model as a tool result. The model cannot reliably tell retrieved data apart from instructions.
- **Sensitive data aggregation:** wording queries to extract and combine personal and commercial data from the corpus, such as employee directory contacts, customer contacts and monthly revenue, or sales pipeline deal sizes and notes.
- **Per-call configuration override:** any principal with `bedrock-agentcore:InvokeHarness` can send a different model, system prompt or tool set on a single call (F-04). Because the execution role can invoke any foundation model and start Browser and Code Interpreter sessions (F-07), an override is not limited by IAM.
- **Hallucinated policy:** confidently stating policy details or SLA terms that aren't in the documents, which employees may then act on.
- **Content generation for social engineering:** writing convincing internal phishing emails or fake announcements that reuse real names, titles and policy wording from the knowledge base.
- **Denial of wallet:** high-volume or maximum-length requests that drive up token costs. Each request can run up to 75 iterations and 1 hour, and the gateway has no rate limits.

## 3. Usage

### 3.1 Intended Use

Titan Text Embeddings V2 is used only for semantic retrieval. At **ingest** it embeds each chunk of the 30 Northstar documents into the vector store. At **query** time it embeds the Retrieve query so that the knowledge base can find the top 5 most similar chunks. **The same model and dimensions (1,024, FLOAT32) must be used on both sides.** Changing either one requires a full re-index.

### 3.2 Out of Scope Usage

- Text generation, summarization or question answering. It cannot produce text.
- Classification or other decisions made on its vectors without a separate validated model
- Images or multimodal input (that would need Titan Multimodal Embeddings, a different model)
- Inputs over 8,192 tokens without chunking. Longer input is rejected or must be split first.
- Treating vectors as anonymized data. Embeddings can be partially inverted to recover the source text, so they are as sensitive as the chunks they encode.

### 3.3 Misuse or Malicious Use

- **Retrieval hijacking / embedding poisoning:** a document crafted to sit near many common queries in vector space, such as one packed with policy keywords, gets retrieved for unrelated questions and delivers attacker content, including prompt-injection payloads, to Claude.
- **Embedding collision / displacement:** a malicious document is made to look similar to a trusted one (for example `security_policy.docx`), so that it outranks or replaces the real policy in the top 5.
- **Embedding inversion:** an attacker who gains read access to the vector store reconstructs approximate source text, including PII, from the stored vectors.
- **Out-of-band embedding use:** a principal with `bedrock:InvokeModel` on Titan uses it to optimize adversarial documents offline before planting them in S3.

> **Finding F-03: sensitive data in a single, undifferentiated index.** Personal data (employee and customer contacts) and confidential commercial data are indexed next to general policy documents. The data source has `aclEnabled: false`, so there is no per-document or per-user access control at retrieval: every user of Northstar Assist can retrieve every chunk. *Recommendation:* remove or separate sensitive datasets, or enable ACL or metadata filtering tied to the caller's role, and add a Bedrock Guardrail with PII masking on outputs.
